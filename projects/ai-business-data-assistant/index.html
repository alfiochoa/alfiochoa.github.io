AI Business Data Assistant

Plain-English questions about sales and payment failures. The LLM never writes SQL: it calls eight validated tools.

Open the live demoCode on GitHub

A short silent walkthrough. The diagrams are schematic illustrations, labelled as such in the video.

The problem

A store owner without SQL skills cannot get answers about failed payments, refunds or why revenue dropped.

What it does

  • A chat assistant over a fictional store's sales and payment-failure data (FastAPI, Streamlit, PostgreSQL).
  • The LLM picks from eight validated tools that run parameterized queries. No code path turns free text into SQL.
  • Out-of-scope questions are declined instead of answered from guesswork, and each answer shows the tool calls behind it.
  • Runs on the Groq free tier with a fallback to a second provider.

Evidence

8validated tools, and no free-text SQL path
15.8%April 2024 payment failure rate in a sample answer (269 failed attempts, synthetic data)
  • Tests cover numeric accuracy against hand-written SQL, no-data hallucination, ambiguity and prompt-injection attempts.
  • Sample answer from a live run: failures went from 238 (10.6%) in March 2024 to 269 (15.8%) in April, with a critical payment-gateway outage on April 10 as the likely cause.
