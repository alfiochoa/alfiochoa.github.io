n8n Automation Hub

Nine n8n workflows built for the failures automation usually hides: duplicates, dropped tickets, silent scrapers.

Try the demo pageCode on GitHub

A short silent walkthrough. The diagrams are schematic illustrations, labelled as such in the video.

The problem

Automations can fail without anyone noticing: a lead processed twice, an AI step that timed out and dropped the ticket, a scraper that “succeeds” with zero rows, a webhook nobody noticed was failing.

What it does

  • Lead intake: validate, normalise, dedupe on an idempotency key, enrich, score 0-100, route hot, warm or cold, store and notify.
  • AI support triage: an LLM drafts the category, urgency and reply, the output is schema-checked, and a keyword classifier takes over if the LLM fails, with the reason shown. Nothing is sent automatically.
  • A polite price scraper, an FX alert, an error handler with structured logs, a daily health report and dead-letter replay that reuses the original idempotency key.
  • Nine workflows in total, including two sub-workflows.

Honest limits

  • The demo server runs on a free tier and sleeps when idle: the first request can take 30-90 s.
  • 512 MB of RAM is enough for a demo, not for sustained traffic.
  • Demo data is synthetic and pruned after 48 hours.
  • n8n is not included in the repository and is licensed separately (Sustainable Use License). The repository's own code is MIT.
