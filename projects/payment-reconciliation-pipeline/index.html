Payment Reconciliation Pipeline

Four sources in, one exceptions report out. Nine rule-based checks find what does not match.

See the sample reportCode on GitHub

A short silent walkthrough. The diagrams are schematic illustrations, labelled as such in the video.

The problem

Payouts do not match orders, and the mismatches are found by checking spreadsheets by hand.

What it does

  • Reads a payment export (CSV/JSON), an orders CSV, a mock paginated orders API with 429 retry handling, and refund tickets.
  • Validates every row with Pydantic. Rejected rows are logged and counted, never silently dropped.
  • Deterministic pandas rules detect nine exception types and write exceptions.csv and a summary.html report.
  • Re-runs produce byte-identical reports.

Honest limits

  • The orders API is a local mock.
  • Matching is by order id only.
  • The fee check assumes a flat 2.9% + 30c.
  • Real exports need a column-mapping adapter.
